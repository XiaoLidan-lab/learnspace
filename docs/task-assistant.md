# 第三阶段开发记录 · 2026-10-16

后续更新：第四阶段已将 PDF 邻页读取升级为全文索引与相关片段检索。当前能力与真实云端验收见 [第四阶段记录](phase4-validation.md)；下文保留第三阶段的历史验收范围。

## 代码审查与实现取舍

现有任务的 moduleStates、按 taskId 过滤的笔记、WorkspaceBus、来源跳转、AI 登录鉴权、限流、55 秒服务端超时、useAI 过期响应保护和云端工作台快照均可复用。测验原来仅有当前题目、答案与 submitted 状态；任务没有反馈、助手记录、调整历史和总结。

本阶段按依赖顺序补充：
1. 测验提交快照、用户自评与掌握证据；按指定任务构建有上限的上下文。
2. 复用 /api/ai 增加 taskAssist 操作，在现有任务面板中提供问答、下一步推荐和计划建议。
3. 完成任务后自动总结；所有新增记录跟随原 IndexedDB 和云端 payload 保存。

没有增加数据库表、Workflow 执行器、向量数据库或独立聊天系统。既有 005 迁移已足够，无需重新执行。云端总快照仍受 5 MB 限制。

## 行为与控制权

- 任务助手只读取指定任务的模块状态、最近八篇笔记、最近成果、卡片、最近提交的测验和最近反馈；不读取其他任务或自由学习正文。总结与调整不传历史问答，普通问答只沿用同一上下文的历史，并移除旧的临时引用编号。用户自评具有独立证据编号。
- 绑定 PDF 在本机提取当前页、下一页、上一页，每次最多六页、每页 2500 字；所有证据正文合计最多 12000 字。显示截断、缺失文件、加密/读取失败与 OCR 不支持情况；不抓取网页、不自动转写视频。
- 证据采用当前请求内的 ID，保存内容类型、模块、笔记、PDF 文件版本及页码。模型引用必须属于提供的证据，模块引用必须属于工作台。笔记、AI 内容、未分类卡片均不会标为原始资料。
- 回答和总结保存引用时的快照；来源删除、文件缺失或版本变化时明确提示，不能跳到错误笔记或伪装已恢复。
- 问答和建议手动触发。下一步优先提示当前错题或未完成步骤；可使用当前有效 AI 建议，点击只定位已有模块，不自动执行动作。
- 计划建议先展示完整拟议顺序、保留/修改/新增/移除的差异；需要用户确认应用。取消、格式错误或计划过期时原计划不变。已完成或关联成果的步骤不允许被移除。
- 模型回显的 done/hasArtifacts 只验证类型后丢弃，不能改变完成状态。确认应用只修改步骤，保留成果、模块内容和最近十次调整前计划。
- 步骤完成情况与掌握证据分离。每个测验模块取最近一次提交；仅选择题按已有参考答案判分，简答不自动计分。展示逐题证据、样本范围、成果数和用户自评，不给出总体掌握百分比。
- 显式复用其他任务内容时，复制测验题目但清空作答、提交和测验历史，避免把别的任务成绩当作当前任务的掌握证据。
- 新完成任务会在用户完成确认后自动生成学习过程、核心知识/成果、薄弱环节与复习建议。失败可重试，可取消；完成状态不依赖 AI 服务是否成功。打开历史任务不会自动上传其内容。
- 切换任务、上下文变化或收起面板会取消旧请求并阻止过期结果写入；取消请求不等于模型提供方一定停止计费。
- 助手记录最多十二次、反馈二十次、每模块测验历史二十次；再次打开可重新预览仍适用的已保存建议。新内容使旧回答/总结显示过期提示。

## 主要文件

- src/taskAssistantSchemas.ts：请求、结果、证据、反馈、计划与总结校验。
- src/taskIntelligence.ts：上下文隔离、证据配额、掌握情况、下一步和计划应用。
- src/taskResources.ts、src/pdfDocument.ts：复用 PDF.js 提取与版本定位。
- src/TaskCoach.tsx、src/TaskPanel.tsx：任务内问答、自评、预览确认和完成总结。
- src/LearningModules.tsx、src/model.ts、src/tasks.ts、src/cloudData.ts：测验历史、任务字段、显式复用及持久化兼容。
- server/api.ts：复用 AI 鉴权、超时、限流和模型配置。
- tests/task-intelligence.test.ts：新增隔离、来源、掌握证据、确认应用及持久化回归。
- scripts/learning-browser-check.ts --synthetic --coach-fixture：只在回环地址创建合成身份、独立任务与本地测试数据库，调用真实配置模型；生产入口不引用它。

## 验证与限制

自动化覆盖模型引用越界、未知模块、不可移除步骤、过期计划、只读标记回显、带引用方案应用、任务间正文/问答隔离、测验复用重置、PDF 绑定及页码/版本、取消/缺失/读取失败、IndexedDB 与云端序列化、独立副本笔记引用重映射。完整回归 52 项，包含原有 AI、布局、模板隐私、权限和部署入口检查。

Safari 真实模型验收使用本机合成环境，未修改已有真实工作台、未发布或部署。模型曾输出多余只读字段，已安全归一化并增加测试；完成总结中的空下一步使用受控回顾提示，括号形式引用仅作标准化后仍须通过白名单校验；来源引用不能证明其逐句支持全部结论，仍需要用户核验。AI 可能过度推断或补充资料未直接支持的机制，结构校验不能验证语义真实性。PDF 不具备全文检索、OCR 或语义检索；掌握情况也不是经过独立验证的学习诊断。


### 浏览器实测记录

- Safari + 真实配置模型：A 任务读取资料文本、笔记、卡片和 0/1 错题，返回限定来源的回答；B 任务只读到其独有“紫色鲸鱼”文本，笔记与测验为空，没有 A 的助手记录。
- 引用快照展开及回跳定位到正确的任务文本模块；下一步推荐可一键进入错题模块。PDF 的绑定/页码/版本与取消分支由自动化覆盖，本次 Safari 未完成原生文件选择器中的合成 PDF 上传。
- AI 建议将两步计划增为三步：预览时原计划仍是两步，取消确认保持不变；确认后新增步骤、调整顺序和一次历史计划均保存。带引用方案确认时的异常已修复并加入回归。
- 步骤 3/3、关联笔记并完成任务后自动生成学习过程、核心知识、薄弱环节和复习建议；掌握情况仍显示“需要巩固”。重新打开、保存自评不会改变步骤完成情况。
- 请求执行中切换 B → A 后，A 未出现 B 的响应或对话。历史回答和总结在上下文变化后提示过期，更新失败保留旧总结并允许重试。
- 隔离验收的数据库在服务重启后重建，触发了版本冲突保护；本地内容保持可用。第三阶段未重新写入真实 Supabase；新增字段的云端序列化/恢复与 RLS 回归通过。

- 最终已通过真实模型更新包含用户反馈的总结，引用列表显示“用户自评与学习反馈”，无过期提示；此前更新失败时旧总结始终保留。反馈内部 ID 不发送给模型，避免其与可引用证据 ID 混淆。

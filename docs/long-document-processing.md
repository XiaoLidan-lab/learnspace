# 整篇文档处理

## 用户操作

1. 在文件阅读模块导入 PDF、Markdown、纯文本或当前已支持的 Word 文件。
2. 点击底部“提问”“生成导图”“生成练习”，或在标准 AI 工具的“学习材料”中选择文件并设为“整篇文档”。知识卡片的快捷入口仍用于选区；也可在卡片工具内主动选择整篇材料。
3. 针对具体问题提问时，系统从完整本地索引检索相关片段；没有命中会明确反馈，不静默使用开头代替。
4. 概述全文、生成导图、卡片或练习时，短文直接处理，长文逐段提取后合并。处理状态显示当前文件、分段进度和取消按钮；成功后显示处理范围。
5. 失败保留原结果，重新生成复用已完成的本地分段分析。切换任务、修改材料或取消后，过期结果不会写入当前工具。

## 实现与兼容

- 复用 `pdfIndex` 的可恢复全文索引、分页缓存、分块及关键词检索，按批次读页；不把完整长文塞进模块正文或 Supabase 快照。
- `documentProcessing.ts` 为标准工具组装材料；每段最多 6000 字符，分段摘要最多 1800 字符，多层合并直到满足材料预算。单次请求、来源快照及云端结构仍保留原有大小校验。
- `documentDigest` 复用现有认证、AI 配置、超时、服务端限流与输出校验。浏览器按顺序执行并节流，不并发启动大量分段请求，不引入后台执行器。
- 本地派生摘要缓存按工作台、任务、模块、文件版本和内容哈希隔离，最多 512 条。缓存不包含原文；正文仍在原文件和已有阅读索引。缓存不可用不应丢失成功的分析结果。
- 最终材料快照、来源和处理范围保存在原有任务隔离模块状态里，沿用现有云端 JSON 存储，不需要 SQL 迁移。
- 自定义 AI 模块的命名字段上限及旧数据格式保持兼容；本次长文处理针对标准学习工具，不扩大任意自定义 Prompt 的输入上限。

## 限制

- 摘要是有损压缩，全文分段都参与分析，不代表保留每个细节或生成覆盖每个知识点的题目；需要精确数字、公式或引用时，应检索原文确认。来源页码是参考定位，不能冒充逐项证据。
- 超过 128 个分析分段的长文档会要求按章节拆分，在该文件调用 AI 前反馈。该保护用于控制单次操作的耗时与请求量。
- 扫描 PDF 或存在无法提取正文的页面，不能标为完整正文分析；当前不支持 OCR。
- 本机文件需可用。分段缓存仅在本机，失败或取消后的续用不等于跨设备恢复中间处理进度。

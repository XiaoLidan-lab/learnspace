# AI 配额与异常协议：阶段 2

本文件对应 RR-002/003 的仓库实现。没有执行真实迁移、配置密钥或部署；不代表生产门禁已关闭。

## 最小架构

- 沿用 Express/Vercel + Supabase。新增 `008_ai_quota.sql`，不改既有工作台、笔记、文件或账号数据。
- 一个 `learnspace_ai_quota` RPC，提供 begin/reserve/finish。短事务 advisory lock 将跨实例检查与扣额串行化；时间由数据库决定，锁等待最多 2 秒。
- 配额策略、计数、请求元数据为三张独立表。RLS 开启，无浏览器角色策略；表权限撤销；RPC 只授予 service_role。服务端先以用户 Token 调用 getUser，使用验证结果作为 user_id，不接收客户端 userId。
- 每次供应商调用前扣除保守额度：messages 的 UTF-8 JSON 字节数 + 每条消息 1024 的协议余量 + 本次输出 Token 上限。失败、取消、崩溃均不退额；布局校验修复的第二次调用单独扣额；全文每个分段独立入账。拒绝扣额就不调用供应商。
- 该额度是保守的准入单位，不是准确 Token 统计、人民币账单或充值余额。不同模型价格、隐藏思考 Token、附加收费及供应商是否遵守输出参数仍需核实，不能据此承诺绝对金额上限。
- 请求总期限 50 秒，配额 RPC 单次最多 4 秒；保留 Vercel `maxDuration=60`。每用户请求 lease 为 90 秒；超时/客户端中断后保留 lease 到期，避免上游尚未停止时立即重试。正常结束释放；释放失败等待 TTL。客户端取消不等于供应商停止计费。

## 重复请求与失败保护

- 前端发送 UUID `Idempotency-Key`。相同 ID 在 7 天元数据保留期内不重复执行；返回 409，不保存或重放模型正文。手动重试为新 ID，会再次扣额。
- 即使客户端换 ID，同一用户正在执行的相同输入哈希也返回 409；不同输入仍受并发限制。数据库只保存 SHA-256、用户 ID、请求 ID 和时间，不保存正文、Token 或模型结果。
- 配额表/RPC 不存在、缺少服务端密钥、网络或锁超时均拒绝新 AI 请求（503）；没有进程内回退。普通本地模块不依赖配额服务。
- 错误统一 `{error: string, code: string, retryAfter?: number}`，频率/并发的 429 同时返回 Retry-After（预算耗尽没有承诺的恢复时间）。400/413 为 JSON；未知异常 500 不回显内部错误；模型失败 502。平台网关仍可能生成 HTML，前端以安全通用说明处理。
